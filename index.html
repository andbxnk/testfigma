ส่วนที่ 1: กระบวนการคิดเชิง UX (UX Process & Problem Solving)

วิจัยผู้ใช้, สกัด Pain Point, ตั้งโจทย์ HMW และเขียน User Flow

สรุปขั้นตอนการทำ UX Research เพื่อไม่ให้ตกหลุมพรางการ "เดาเอาเอง" โดยเน้นที่มาของข้อมูล และการสกัดปัญหาไปสู่การออกแบบฟีเจอร์อย่างเป็นระบบ

1. User Research (การวิจัยผู้ใช้) มาจากไหน และหาอย่างไร?

Primary Research (วิจัยทางตรง)

เก็บข้อมูลใหม่จากผู้ใช้จริง

คือการเข้าหา "ผู้ใช้จริง (Target Users)" โดยตรงเพื่อค้นหาพฤติกรรม ข้อจำกัด และความรู้สึกที่แท้จริง

1. User Interview (สัมภาษณ์เชิงลึก) Qualitative

คุยแบบ 1-on-1 เพื่อถามเหตุผล "ทำไม" หาความรู้สึกและแรงจูงใจเบื้องหลัง

2. Contextual Inquiry (สังเกตการณ์หน้างาน)

ไปนั่งเฝ้าดูผู้ใช้ทำงานในสภาพแวดล้อมจริง เพื่อเห็นปัญหาที่ผู้ใช้เองก็พูดไม่ถูก

3. Surveys / Questionnaires (แบบสอบถาม) Quantitative

ส่งแบบสอบถามเน้นปริมาณมากเพื่อดูแนวโน้มสถิติ ตัวเลขสัดส่วน

4. Usability Testing (การทดสอบการใช้งาน) Behavioral

ให้ผู้ใช้ทดลองกด Prototype หน้าจอจริงแล้วสังเกตจุดติดขัด (Friction)

Secondary Research (วิจัยทางอ้อม)

ศึกษาข้อมูลที่มีอยู่แล้ว

คือการรวบรวมข้อมูล ข่าวสาร สถิติ หรือการวิเคราะห์ที่มีผู้รวบรวมไว้ล่วงหน้า

1. Competitor Analysis (วิเคราะห์คู่แข่ง)

ศึกษาสิ่งที่แอปคู่แข่งทำดี และจุดอ่อนที่คู่แข่งมองข้าม

2. Product Analytics & Heatmaps

ดูข้อมูลสถิติเดิม เช่น Drop-off Rate (จุดที่คนกดเลิกใช้) หรือจุดที่คนกดมากที่สุด

3. Desk Research & Review Mining

อ่านรีวิวแอปบน App Store / Play Store สกัดข้อร้องเรียนของผู้ใช้

2. Pain Point คืออะไร, มาจากไหน และหาอย่างไร?

DEFINITION

Pain Point คืออะไร?

คือ "อุปสรรค ความหงุดหงิด ความยากลำบาก" ที่ผู้ใช้พบเจอขณะพยายามทำภารกิจใดภารกิจหนึ่งให้สำเร็จ

ORIGIN

มาจากไหน?

มาจากขั้นตอน **Empathize & Research** (การฟังเสียงบ่น, สังเกตเห็นจุดติดขัด, อ่านตั๋วบริการลูกค้า)

METHODOLOGY

หาอย่างไร? (4 เครื่องมือ)

ใช้ Empathy Map, 5 Whys, Affinity Diagram และ Customer Journey Map

Empathy Map

จำแนกข้อมูลผู้ใช้เป็น 4 ช่อง:

  • Says: สิ่งที่พูด
  • Thinks: สิ่งที่คิด
  • Does: สิ่งที่ทำ
  • Feels: ความรู้สึก
5 Whys Analysis

ถามคำว่า "ทำไม" ต่อเนื่องกัน 5 ครั้ง เพื่อสาวหา **Root Cause (สาเหตุรากเหง้า)** ที่แท้จริง ไม่หลอกตัวเองด้วยปัญหาฉาบฉวย

Affinity Diagram

นำข้อมูลบ่นและข้อสังเกตเขียนใส่ Sticky Notes แล้วจัดกลุ่ม (Cluster) ปัญหาที่มีแพตเทิร์นคล้ายกันเข้าด้วยกัน

Customer Journey Map

กางเส้นทางขั้นตอนการใช้แอป และดูกราฟอารมณ์ (Emotion Curve) จุดที่กราฟตกต่ำสุด คือจุด Pain Point

3. การแปลง Pain Point เป็น Solution ด้วย "How Might We (HMW)"

**HMW (How Might We...)** คือการเปลี่ยนคำบ่นหรือปัญหาให้กลายเป็น **"คำถามเชิงบวกชวนคิดโซลูชัน"** เพื่อเป็นสะพานเชื่อมระหว่างระยะ Define ไปสู่ Ideation

ระยะ (Stage) Pain Point (ข้อขัดข้องของผู้ใช้) HMW Statement (การตั้งโจทย์) Solution / Feature (ฟีเจอร์ที่ได้)
แอปกรอกที่อยู่ "กรอกที่อยู่จัดส่งยาวมาก พิมพ์ในมือถือเสียเวลาทำให้อยากยกเลิก" "เราจะทำอย่างไรให้ผู้ใช้ระบุที่อยู่ได้โดยไม่ต้องพิมพ์ข้อความยาวๆ?" ฟีเจอร์ปุ่ม "ดึงพิกัด GPS ปัจจุบัน" + ค้นหารหัสไปรษณีย์แล้วเติมอำเภออัตโนมัติ
แอปสั่งอาหาร "หิวข้าวตอนเที่ยง แต่เสียเวลานั่งเลือกเมนูนานเกินไป" "เราจะทำอย่างไรให้ผู้ใช้สั่งอาหารชุดเดิมที่ชอบได้ภายใน 2 คลิก?" ฟีเจอร์ "Re-order ปุ่มสั่งซ้ำเมนูโปรด" บนหน้าแรก

4. User Flow คืออะไร & สัญลักษณ์มาตรฐาน Flowchart

User Flow ประกอบด้วย 4 องค์ประกอบหลัก:

  • 1. Entry Point: จุดเริ่มต้นเข้าสู่ระบบ (เช่น เปิดแอป, คลิก Banner)
  • 2. Action Steps: ขั้นตอนการทำงานที่ผู้ใช้กระทำ (เช่น กดปุ่ม, กรอกฟอร์ม)
  • 3. Decision Points: จุดตัดสินใจหรือเงื่อนไขระบบ (เช่น ล็อกอินหรือยัง? ยอดเงินพอหรือไม่?)
  • 4. Success State: จุดสิ้นสุดเป้าหมายสำเร็จ (เช่น สั่งซื้อสำเร็จ, แสดงใบเสร็จ)

สัญลักษณ์ Flowchart มาตรฐานที่ออกสอบ:

Oval
Start / End Node: จุดเริ่มต้น หรือ จุดสิ้นสุดของ Flow
Rectangle
Screen / Process Action: หน้าจอ หรือ การกระทำของผู้ใช้
Diamond
Decision Node: จุดตัดสินใจเงื่อนไข (มีทางออก Yes / No)
ส่วนที่ 2: สรุปฟีเจอร์เครื่องมือ Figma (Comprehensive Figma Cheat Sheet)

ตารางสัญลักษณ์, คีย์บอร์ดลัด, คุณสมบัติเด่น และการนำไปใช้

สรุปครบทุกเครื่องมือหลักที่ออกสอบ พร้อมสัญลักษณ์จำง่าย ❖ Component, ◇ Instance, || Auto Layout, Variants และ Design Tokens

เครื่องมือ (Tools) สัญลักษณ์ / Shortcut ลักษณะเด่น (Key Behavior) นำไปใช้ทำอะไร (Use Case)
# Frame # / F / Shift + F มีขนาดขอบเขตอิสระของตัวเอง, ใส่ Background, Auto Layout, Constraints และ **Clip Content** ได้ ใช้ทำเป็นหน้าจอแอป (Screen) หรือ Container ครอบ UI Element
[ ] Group Cmd + G / Ctrl + G ไม่มีขนาดของตัวเอง ขึ้นกับวัตถุรวมกัน, เวลาขยาย Group วัตถุข้างในจะ **Scale ยืดหดตาม** ใช้รวมกลุ่มวัตถุชั่วคราวเพื่อย้ายตำแหน่งพร้อมกัน
❖ Main Component ❖ เพชรทึบ 4 เม็ด / Cmd+Opt+K **แม่พิมพ์หลัก** เมื่อแก้ไขสไตล์หรือตำแหน่งที่ Main Component ตัวลูก (Instance) จะเปลี่ยนตามทั้งหมด สร้างเป็น Master UI Element เช่น ปุ่มมาตรฐาน, Header bar, Navbar
◇ Instance Component ◇ เพชรโปร่ง 1 เม็ด **ชิ้นงานลูก** ที่ก๊อปปี้จากแม่ สามารถ **Override** (เปลี่ยนข้อความ/สี/รูป) ได้โดยไม่กระทบแม่ นำไปวางแปะใช้งานจริงตามหน้าจอต่างๆ
|| Auto Layout || / Shift + A จัดระเบียบวัตถุอัตโนมัติ กำหนด **Padding, Gap, Alignment, Hug Content / Fill Container** ได้ ใช้ทำรายการ List, Button ยืดตามข้อความ, Responsive Layout
❖❖ Variants / Set ❖ ในกรอบเส้นประ รวมกลุ่ม Component เดียวกันแต่ต่างสถานะ (States) เข้าด้วยกันเป็น Set เดียว ให้เลือกสลับใน Inspector รวมปุ่มสถานะ Default, Hover, Pressed, Disabled, Primary, Secondary
◇ Variables / Tokens ◇ ในวงกลม / Variable Panel เก็บค่ากลาง เช่น Color, Number, String, Boolean สลับโหมด Light/Dark Mode ได้ง่าย ใช้ทำ Design System สลับธีมสี หรือทำตัวแปรตัวเลขใน Prototype
📐 Constraints Crosshair / Pin ยึดตำแหน่งวัตถุใน Frame (Top, Bottom, Left, Right, Center, Scale) เมื่อ Frame ยืดหด ทำ Responsive Design ตรึง Navbar ไว้ด้านบน หรือ Floating Button ด้านล่าง
➔ Prototyping ➔ / Prototype Tab เชื่อมสาย Interaction ด้วย **Triggers** (On Click, Hover) และ **Smart Animate** คำนวณการย้ายวัตถุ ทำภาพเคลื่อนไหวจำลองแอปเสมือนจริงให้ผู้ใช้ทดสอบ
[=] Section [=] / Shift + S กรอบครอบแบ่งหมวดหมู่พื้นที่ขนาดใหญ่บน Canvas มาร์กสถานะ Ready for dev ได้ จัดกลุ่มหน้าจอตาม Flow เช่น User Onboarding Flow, Checkout Flow
◐ Boolean Operations Union, Subtract, Intersect, Exclude นำ Shape Vector มาผสาน ตัดทอน หรือหาจุดตัดกัน เพื่อสร้าง Shape รูปทรงใหม่ ใช้ทำ Custom Icon หรือ Graphic Vector โลโก้

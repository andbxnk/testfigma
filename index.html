Figma Canvas & Toolbar Reference

คู่มือสรุปเครื่องมือ Figma ฉบับสมบูรณ์

เจาะลึกกลุ่มเครื่องมือหลัก Canvas Toolbar, Shortcut Keys, สัญลักษณ์, ลักษณะการทำงานเชิงลึก และกรณีใช้งานจริงที่ออกข้อสอบบ่อยที่สุด

1. กลุ่มเครื่องมือเลือก ย้าย และเลื่อน Canvas (Move & Navigation)

↖

Move Tool

เครื่องมือย้ายและเลือกพื้นฐาน

Shortcut: V

ลักษณะการทำงาน: ใช้เลือกวัตถุ, เปลี่ยนตำแหน่ง (X/Y), ปรับขนาดกรอบ Bound (Resizing) โดยไม่ปรับสเกลขนาดตัวอักษร, Stroke หรือ Corner Radius ในการขยาย

💡 ข้อควรจำในข้อสอบ: เมื่อใช้ Move Tool ขยาย Frame ตัวอักษรข้างในจะไม่ใหญ่ขึ้นตาม แต่จะเกิด Text Wrapping หรือระยะล้น
K

Scale Tool

เครื่องมือสเกลขนาดทุกส่วนอย่างได้สัดส่วน

Shortcut: K

ลักษณะการทำงาน: สเกลขนาดวัตถุทั้งหมดตามอัตราส่วนคงเดิม (Proportional Scaling) รวมถึง Font Size, Stroke Thickness, Corner Radius ให้ใหญ่/เล็กตามสัดส่วนสเกล

💡 ข้อควรจำในข้อสอบ: เหมาะสำหรับย่อ/ขยาย Component หรือ Icon ที่ต้องการให้ความหนาของเส้นและขนาดตัวอักษรเปลี่ยนตามสัดส่วน
✋

Hand Tool

เครื่องมือเลื่อนมุมมอง Canvas

Shortcut: H / Spacebar

ลักษณะการทำงาน: กดเพื่อคลิกลากพานิชย์ (Pan) มุมมองบน Canvas โดยไม่มีการคลิกเลือกหรือเคลื่อนย้ายตำแหน่ง Layer ใดๆ บนพื้นที่ทำงาน

💡 Tips การใช้งาน: สามารถกดปุ่ม Spacebar ค้างไว้ขณะใช้เครื่องมืออื่น เพื่อสลับเป็น Hand Tool ชั่วคราวได้ทันที
✂

Slice Tool

เครื่องมือครอบตัดเพื่อ Export

Shortcut: S

ลักษณะการทำงาน: สร้างอาณาเขตสี่เหลี่ยมครอบพื้นที่เฉพาะบน Canvas เพื่อตั้งค่า Export เป็นไฟล์ภาพ (PNG, JPG, SVG, PDF) โดยไม่ต้องแยก Layer วัตถุ

💡 กรณีใช้งานจริง: Export ภาพบางส่วนของดีไซน์ complex ที่รวมกันหลายชั้น หรือตัดเฉพาะ Banner จากหน้า Canvas ขนาดใหญ่

ตารางเปรียบเทียบ: Move Tool (V) vs Scale Tool (K)

คุณสมบัติ Move Tool (V) Scale Tool (K)
การขยายขนาดกรอบ ขยายเฉพาะ Boundary Box สเกลขยายตามอัตราส่วน %
ขนาดตัวอักษร (Font Size) คงที่เท่าเดิม (อาจตัดคำ/ล้น) ขยาย/ย่อสเกลตามอัตราส่วน
ความหนาเส้น (Stroke) ความหนาpx คงที่เท่าเดิม เพิ่ม/ลดความหนาตามสเกล
Corner Radius ค่า Radius เท่าเดิม เปลี่ยนตามอัตราส่วนภาพ

ตารางเปรียบเทียบ: Frame (#) vs Group ([ ])

คุณสมบัติ Frame (# / F) Group (Ctrl+G)
พฤติกรรมขนาด (Bounds) เป็นอิสระจาก Child Layers ผูกติดขนาดรวมของวัตถุด้านในเสมอ
รองรับ Auto Layout รองรับ ( Shift + A ) ไม่รองรับ (แปลงเป็น Frame ก่อน)
Constraints & Padding กำหนดการยึดขอบได้อิสระ ไม่มี Constraints เป็นของตนเอง
Clip Content ซ่อนส่วนล้นขอบได้ (Clip) ไม่สามารถ Clip Content ได้

2. กลุ่มเครื่องมือสร้างโครงสร้าง รูปทรง ข้อความ และ Components

# Frame F / A

ผืนผ้าใบหลักรองรับ Layout, Constraints, Auto Layout และการทำ Prototype ถือเป็น Container พื้นฐานสำคัญที่สุดใน Figma

[=] Section Shift + S

ใช้ครอบจัดหมวดหมู่ Frame ขนาดใหญ่ ช่วยให้นักพัฒนามองเห็นขอบเขตชัดเจนใน Dev Mode และจัดระเบียบ Canvas ขั้นสูง

Component Icons ❖ Main / ◇ Instance

❖ Main Component: ต้นแบบหลัก
◇ Instance: สำเนาที่สืบทอดคุณสมบัติ
❖❖ Component Set: รวบรวม Variants

|| Auto Layout Shift + A

สร้าง Responsive Layout อัตโนมัติ ปรับระยะห่าง Padding, Gap และทิศทาง (Horizontal/Vertical) อัตโนมัติเมื่อข้อความหรือวัตถุเปลี่ยน

█ Shape Tools R, O, L, P

Rectangle (R), Ellipse (O), Line (L), Arrow (Shift+L), Polygon, Star, และ Pen Tool (P) สำหรับวาด Vector Paths

❖ Variables / Tokens Design System

การเก็บค่า Color, Number, String, Boolean เป็นตัวแปรส่วนกลาง รองรับการสลับ Dark/Light Mode และ Theme

UX Research & Methodology

สรุปกระบวนการคิดออกแบบ UX

สรุปหลักการสำคัญของการวิจัยผู้ใช้, Empathy Framework, การวิเคราะห์รากเหง้าปัญหา (Root Cause Analysis), การตั้งคำถาม HMW และผังกระบวนการทำงาน User Flow

Primary Research (ข้อมูลปฐมภูมิ)

เก็บข้อมูลตรงจากผู้ใชัจริงด้วยตนเอง

การลงมือเก็บข้อมูลใหม่โดยตรงจากกลุ่มเป้าหมาย เพื่อทำความเข้าใจพฤติกรรม ความรู้สึก และปัญหาเชิงลึกเฉพาะบริบท

  • User Interviews: การสัมภาษณ์เชิงลึกแบบ 1-ต่อ-1
  • Contextual Inquiry: สังเกตการณ์พฤติกรรมในสภาพแวดล้อมจริง
  • Usability Testing: ทดสอบการใช้งาน Prototype กับผู้ใช้จริง

Secondary Research (ข้อมูลทุติยภูมิ)

ศึกษารวบรวมจากข้อมูลที่มีอยู่แล้ว

การรวบรวมและวิเคราะห์ข้อมูลจากแหล่งข้อมูลที่มีการบันทึกไว้แล้ว เพื่อหาแนวโน้ม ตลาด และเปรียบเทียบคู่แข่ง

  • Competitor Analysis: วิเคราะห์จุดแข็ง-จุดอ่อนคู่แข่ง
  • App Review Mining: อ่านคอมเมนต์ด่า/ชมใน App Store / Play Store
  • Academic & Market Reports: รายงานสถิติและงานวิจัยอุตสาหกรรม

Root Cause Analysis: 5 Whys Framework Simulator

เครื่องมือถาม "ทำไม" 5 ระดับเพื่อค้นหาต้นตอที่แท้จริงของปัญหา (Root Cause) ไม่ใช่แก้แค่ที่อาการภายนอก (Symptom)

Empathy Map Framework (4 Quadrants)

🗣 SAYS (คำพูด)

ข้อความ คำพูดตรงๆ ที่ผู้ใช้พูดระหว่างสัมภาษณ์ เช่น "แอปรวมเงินยากมาก"

🧠 THINKS (ความคิด)

สิ่งที่อยู่ในใจแต่ไม่ได้พูดออกตรงๆ เช่น "กังวลว่าระบบจะหักเงินซ้ำ"

👁 DOES (การกระทำ)

พฤติกรรมที่สังเกตเห็น เช่น กดยกเลิกกลับไปหน้าเดิม 3 รอบก่อนกดยืนยัน

❤️ FEELS (อารมณ์)

อารมณ์ความรู้สึก เช่น สับสน หงุดหงิด วิตกกังวล ประทับใจ

How Might We (HMW) Framework

เทคนิคการเปลี่ยน Pain Point (คำบ่น/ปัญหา) ให้กลายเป็น คำถามเปิดกว้างที่จุดประกาย Solution Design

❌ Pain Point: "ผู้ใช้บ่นว่ากรอกฟอร์มที่อยู่ยาวเกินไปและพิมพ์ผิดบ่อย"
✅ HMW Statement: "เราจะทำอย่างไรให้ขั้นตอนระบุที่อยู่จัดส่งสะดวกรวดเร็วและลดการพิมพ์ผิดให้ได้มากที่สุด?"

Standard User Flowchart Symbols & Walkthrough

สัญลักษณ์มาตรฐานสากลในการเขียน User Flow Diagram ที่ออกข้อสอบบ่อยที่สุด
